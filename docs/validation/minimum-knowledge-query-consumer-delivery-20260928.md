Do not use the legacy unauthenticated `/v2/module/call`, browser-held SD credentials, an SD search HTTP response in place of the module envelope, or a second retrieval implementation. Endpoint/DTO strings cannot be inserted until the public owner freezes them; `MINIMUM_PUBLIC_ROOT_HANDOFF_20260928.md` records that dependency.

There is one **conditional browser input hunk**, not a response hunk. `KnowledgePage.tsx:145-147,244-259` initializes and then automatically selects an enabled host model; `:480` sends its ID as `model_config_id`. The current public `search_knowledge_base` in `resources.py:124-130` rejects that field. Thus a normal loaded page with an enabled model receives an accurate public error even for one KB. The public read facade must freeze whether and how the selected PD model ID is bound to its sole approved retrieval model. Once fixed, the adapter owner should apply only that named input mapping/validation in `knowledge-host-adapter.tsx` (or the UI owner should stop offering an unsupported selection with explicit user-visible semantics). Do not silently drop the chosen ID, reinterpret it as an SD model ID, or choose a fallback model. This issue blocks a source-level claim that the formal page query is connected; it does not require changing the already correct result/citation projection.

Requests without exactly one selected KB, or with multiple KBs, are outside this one-document minimum mapping. `planKnowledgePublic` intentionally does not collapse them to the first KB. They must not be reported as publicly backed by this evidence; a later exact bounded contract is needed before treating them as supported. The original `KnowledgeSearchResponse` remains a structured evidence object, so the model's actual citation in a normal conversation still requires the independent fresh run and cannot be inferred from source inspection.
